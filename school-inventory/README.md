# Школьный инвентарь

Первая исходная версия адаптивного приложения учёта школьного имущества.
Стек: Next.js 15 / React 19 / TypeScript / PostgreSQL 16 / Prisma 6 / ExcelJS.
Интерфейс: собственный CSS без UI-зависимостей; карта: SVG поверх PNG/JPEG.
Авторизация: серверные сессии с криптографически случайными токенами, SHA-256-хешами в БД и bcrypt для паролей.

**Статус:** исходники подготовлены, но сборка Next.js, генерация Prisma и интеграционные тесты в среде создания архива НЕ запускались. Требуется проверка на тестовом сервере. Это не готовая сертифицированная бухгалтерская система и не основание сразу открывать сервис в интернет.

## Реализованные модули

- Вход, выход, роли ADMIN / OPERATOR / VIEWER, отключение пользователей и сброс их сессий при изменении доступа.
- Направления IT / HOUSEHOLD / ALL: общие помещения, раздельный доступ к имуществу, материалам и документам.
- Одна школа на установку; schoolId проверяется сервером. Самостоятельной регистрации школ нет.
- Карточки имущества: инвентарный номер (строка), категория, стоимость, дата, состояние, ответственное лицо, серийный номер, дополнительные поля.
- Помещения, корпуса, этажи и текстовые зоны хранения; редактирование без удаления истории.
- Перемещения имущества и история действий.
- Номенклатура материалов, единицы измерения, минимальный остаток, приход и перемещение партий с точной ценой.
- Списание имущества и материалов: черновик, проведение, отмена. Проведение меняет остатки в Serializable-транзакции. При конфликте нужно повторить операцию.
- Отмена проведённого акта администратором возвращает остатки, с причиной в журнале. Это упрощённая отмена, не бухгалтерское сторно.
- Архив списанных объектов без удаления карточек; местоположение на момент списания сохраняется.
- Печатные акты с подписями и браузерной печатью в PDF. Документы не являются электронной подписью.
- Инвентаризации индивидуального имущества: снимок ожидаемого списка, отметки фактического помещения, закрытие без автоматической правки учёта.
- Интерактивные планы PNG/JPEG: загрузка, несколько планов, рисование многоугольников, привязка помещений, переход к списку имущества.
- Excel: выбор листа и заголовка, сопоставление колонок, предварительная проверка, ошибки и атомарный импорт новых карточек; экспорт имущества.
- QR-этикетка на объект с непрозрачным кодом `SINV1:…`; встроенный сканер (камера, фото, ручной ввод) открывает карточку, а во время инвентаризации ставит отметку.
- Вход только с устройств, подтверждённых администратором; 2FA (TOTP); ограничение попыток по email и IP.
- PWA: установка на телефон, данные не кэшируются на устройстве.
- Сводки стоимости, группировки имущества по помещениям, категориям, ответственным и направлениям.
- Адаптивный интерфейс и журнал последних 300 событий (полная история остаётся в БД).

## Быстрый запуск через Docker

Требуются Docker Engine и Docker Compose v2. Команды выполнять из корня проекта.

```sh
cp .env.example .env
```

Измените `.env`:

```dotenv
DB_PASSWORD=длинныйСлучайныйПарольТолькоЛатинскиеБуквыИЦифры
APP_ORIGIN=http://localhost:3000
ADMIN_EMAIL=admin@school.local
ADMIN_PASSWORD=уникальный-пароль-не-менее-14-символов
SCHOOL_NAME=Моя школа
```

Для DB_PASSWORD используйте только ASCII-буквы и цифры, чтобы не требовалось URL-кодирование в DATABASE_URL. Лучше сгенерировать 32 случайных символа. DATABASE_URL из примера нужен локальной разработке; Compose переопределяет его автоматически.

```sh
docker compose build
docker compose up -d db
docker compose run --rm app npx prisma db push
docker compose run --rm app npm run seed
docker compose up -d app
```

Откройте http://localhost:3000 и войдите с ADMIN_EMAIL / ADMIN_PASSWORD.
Seed создаёт школу, администратора и три помещения. Повторный seed не меняет пароль существующего пользователя.

Порт привязан только к 127.0.0.1. На удалённом сервере используйте HTTPS reverse proxy либо SSH-туннель:

```sh
ssh -L 3000:127.0.0.1:3000 user@server
```

Не публикуйте PostgreSQL в интернет. `docker compose down -v` **удаляет данные**.

## Локальная разработка

Установите Node.js 22 и PostgreSQL 16, создайте базу и укажите DATABASE_URL в `.env`.

```sh
npm install
npx prisma generate
npx prisma db push
npm run seed
npm run dev
```

Сначала выполните проверки:

```sh
npm run test
npm run typecheck
npm run build
npm audit
```

Версии заданы диапазонами. Lock-файл здесь не сгенерирован: npm не запускался. После первого успешного разрешения актуальных безопасных зависимостей зафиксируйте `package-lock.json`, замените `npm install` в Dockerfile на `npm ci` и прогоните проверки повторно. Проверяйте актуальные исправления безопасности Next.js и React перед публикацией.

`prisma db push` подходит для первого развёртывания тестовой базы. Перед реальной эксплуатацией сформируйте baseline-миграцию, сохраните её в репозитории и используйте `prisma migrate deploy` для последующих обновлений. Не запускайте экспериментальные изменения схемы на единственной рабочей БД.

## Первичная настройка

1. Настройки → название школы, категории, дополнительные поля. Поля сейчас задаются JSON, не визуальным конструктором.
2. Помещения → создать помещения с однозначными названиями для импорта.
3. Пользователи → завхоз: OPERATOR + HOUSEHOLD; системный администратор: OPERATOR + IT; директор: VIEWER + ALL.
4. Добавить имущество вручную либо через Excel.
5. Материалы → создать номенклатуру → приход партии с ценой, количеством и помещением.
6. Карта → загрузить план → редактор → выбрать помещение → отметить точки → закончить область → сохранить карту.
7. Выбрать имущество → «На списание» → создать черновик → документы → проверить акт → провести.

Для Excel обязательны номер, название, категория, помещение и стоимость. Направление — IT или HOUSEHOLD, по умолчанию IT для пользователей с полным доступом. Объекты с повторяющимся номером не обновляются и не пропускаются молча: импорт блокируется до исправления ошибок. Номера в исходном Excel храните как текст. Импорт ограничен 5000 строками и 5 МБ сжатого XLSX; такой лимит сам по себе не защищает от ZIP-bomb.

Материалы списываются из явно выбранной партии: здесь нет автоматического FIFO или средней себестоимости. Выдача во временное пользование с возвратом пока отдельно не реализована.

## Публикация и безопасность

- Сначала завершить сценарии из ACCEPTANCE.md.
- Доступ из школьной сети/VPN предпочтительнее публичного доступа на первом этапе.
- Для публикации настройте Caddy/Nginx и TLS. Есть Caddyfile.example для Caddy на хосте.
- APP_ORIGIN должен ТОЧНО совпадать с адресом сайта, например https://inventory.example.org, без завершающего слеша. От него зависят Origin-проверка, Secure-cookie и QR-ссылки.
- Ограничьте тело запросов и частоту запросов в reverse proxy. Встроенное ограничение входа привязано к email и требует дополнения IP-лимитами на прокси.
- Вложения карт отдаются только после авторизации, файлы вне public/.
- Закрытая регистрация; права проверяются сервером. Пользователь VIEWER не может выполнять изменения через API.
- Сессия 8 часов, HttpOnly/SameSite=Lax. При HTTPS — Secure.
- Не храните реальные планы школы в публичном Git-репозитории.
- Перед широким доступом добавьте обработку изображений и XLSX в изолированном worker с лимитами памяти/времени, аудит безопасности, CSP, мониторинг и очистку истёкших сессий/попыток входа.
- База в текущей схеме использует строковые идентификаторы без внешних ключей: существование и принадлежность проверяются сервисом. Перед расширением системы рекомендуется добавить отношения/FK и ограничения на уровне БД. Не редактируйте таблицы вручную.
- Точные суммы хранятся Decimal в БД, печатный акт считает Decimal. Сводки интерфейса используют JS Number и не предназначены для бухгалтерской сверки высокой точности.

## Резервные копии

Сохраняйте и базу, и volume `files`, лучше с остановленными изменениями в приложении. Пример согласованной копии с короткой остановкой:

```sh
mkdir -p backups
docker compose stop app
docker compose exec -T db pg_dump -U inventory -d inventory -Fc > backups/inventory.dump
docker compose run --rm --no-deps --user root -v "$PWD/backups:/backup" app tar czf /backup/files.tar.gz -C /app/data .
docker compose start app
```

Команды не образуют надёжный автоматический скрипт: контролируйте exit-коды и возобновление сервиса при ошибке. Копии содержат чувствительные данные, храните их зашифрованными вне основного сервера. Регулярно проверяйте восстановление в отдельной среде.

Восстановление в подготовленную тестовую базу (перезаписывает её):

```sh
docker compose stop app
docker compose exec -T db pg_restore -U inventory -d inventory --clean --if-exists < backups/inventory.dump
docker compose run --rm --no-deps --user root -v "$PWD/backups:/backup" app sh -c 'tar xzf /backup/files.tar.gz -C /app/data && chown -R node:node /app/data'
docker compose start app
```

## Границы версии

Не реализованы: фото и произвольные вложения/подписанные сканы, ремонты и комплекты, возвраты и выдача материалов как самостоятельные процессы, многоступенчатое согласование, DOCX и конструктор форм, электронная подпись, амортизация, автоматические уведомления, импорт материалов, экспорт всей системы одной кнопкой, постраничный API, PWA/offline, встроенный QR-сканер, обнаружение неучтённых объектов в инвентаризации, количественная инвентаризация материалов, произвольные роли/направления, самостоятельная регистрация нескольких школ, перетаскивание вершин и замена изображения существующей карты.

Проект нельзя честно считать реализацией _всех_ возможностей из обсуждения. Это расширяемая первая версия с основными рабочими потоками в исходниках. Дальнейшие задачи перечислены в ROADMAP.md.
