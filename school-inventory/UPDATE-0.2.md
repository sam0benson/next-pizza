# Обновление 0.2 поверх вашей версии

## Важно

Архив не содержит .env, пользовательские файлы и базу. Сохраните свои .env, data/ и volumes Docker. Вход и редактор карты взяты из присланной версии, не заменены старым вариантом. Seed повторять НЕ нужно.

Перед обновлением остановите приложение, сделайте резервную копию PostgreSQL (pg_dump) и data/ (или volume files). Проверьте копию на отдельной установке. Не применяйте update на единственном экземпляре без копии.

## Локальная разработка

1. Остановите npm run dev.
2. Скопируйте исходники обновления поверх проекта, сохранив свой .env и data/.
3. Выполните:

```sh
npm install
npx prisma validate
npx prisma db execute --file prisma/upgrades/0.2.sql --schema prisma/schema.prisma
npx prisma generate
npm run typecheck
npm run test
npm run build
npm run dev
```

SQL создаёт только четыре новые таблицы и индексы. Старые таблицы и данные не изменяет. Выполнять один раз: повторное выполнение завершится ошибкой и откатом транзакции. Если вы уже применили новую схему через db push, SQL выполнять не нужно. Не используйте prisma migrate reset или db push --accept-data-loss.

Это отдельный SQL upgrade для проекта, ранее созданного через db push, а не полноценная история Prisma Migrate. Если вы самостоятельно внедрили migrations, включите эти изменения в свою историю миграций вместо прямого выполнения SQL.

## Docker

После резервной копии и замены исходников:

```sh
docker compose stop app
docker compose build app
docker compose run --rm app npx prisma db execute --file prisma/upgrades/0.2.sql --schema prisma/schema.prisma
docker compose run --rm app npm run typecheck
docker compose run --rm app npm run test
docker compose up -d --force-recreate app
```

Новые модели генерируются при сборке Dockerfile. Не удаляйте volumes.

## Где искать новое

- «Ремонты и выдача»: ремонты, временная выдача, частичные возвраты материалов, комплекты, предупреждения.
- Имущество → нажать инвентарный номер → фото и вложения.
- Документы → открыть акт → подписанные PDF/фотографии внизу страницы.
- Выбранное имущество → массовое перемещение или пакетная печать QR (до 100).
- Настройки → визуальное добавление полей, JSON вводить не требуется.
- Инвентаризация → «Не найдено», экспорт ведомости.
- Материалы → экспорт партий XLSX.
- Журнал → экспорт по диапазону UTC-дат, до 20000 событий.

## Семантика учёта

Материалы выдаются ВРЕМЕННО: складской остаток уменьшается, но стоимость не списывается. Возврат поступает в исходную партию, можно возвращать частями. Остатки на главной и в текущих отчётах показывают склад, НЕ сумму склад+выданное. Реестр выдач хранит невозвращённые количества. Для окончательного расхода используйте акты списания после возврата; конвертация выдачи в расход пока не реализована.

Выдача индивидуального имущества не меняет его учётный кабинет/ответственного: получатель и срок отражаются отдельной записью. До возврата заблокированы перемещение и списание. Ремонт не меняет состояние карточки автоматически.

Комплекты — логическая группировка. Добавление в комплект не перемещает и не списывает объекты.

Вложения: PNG/JPEG/PDF, до 10 МБ, проверки сигнатуры и доступа. PDF скачивается как attachment. Нет антивируса, обработки изображений и проверки PDF на вредоносное содержимое. Не открывайте загруженные файлы из недоверенных источников без проверки. Удаление вложений пока не предусмотрено.

Направление существующей карточки/материала теперь нельзя менять, чтобы не разрывать права на связанные документы и выдачи.

## Реализовано не всё из предыдущего списка

В этом обновлении нет: DOCX, многоступенчатого согласования, произвольных шаблонов актов, количественной инвентаризации материалов, неучтённых находок, полей по категориям, импорта материалов, гарантий и совместимости картриджей, email/push, серверной пагинации, электронной подписи, амортизации, SaaS для нескольких школ и offline-режима.

Не выдавайте текущие печатные формы за утверждённые бухгалтерией документы. Используйте реальные образцы для следующего этапа.

## Обязательная проверка

1. Старый логин, карта, карточки, документы открываются после update.
2. Создать ремонт, изменить этап, завершить; история есть в журнале.
3. Прикрепить фото к карточке и PDF к акту; VIEWER читает, но не загружает; пользователь другого направления не скачивает файл даже по прямому URL.
4. Выдать 5 единиц материала из партии 10: склад 5. Вернуть 2: склад 7, выданный остаток 3. Вернуть 3: склад 10, выдача закрыта.
5. Нельзя вернуть больше выданного, выдать отрицательное или сверх остатка. Два параллельных запроса не должны создавать отрицательный остаток.
6. Нельзя повторно выдать, переместить или списать выданный индивидуальный объект. После возврата операция доступна.
7. Массовое перемещение с недоступным ID отклоняет всю транзакцию.
8. Настройки дополнительных полей сохраняются; ранее записанные скрытые поля не удаляются при редактировании карточки.
9. Пакетная печать QR, экспорт ведомости, журнал по датам и партии материалов открываются корректно.
10. Проверить восстановление копии вместе с вложениями в отдельной установке.

## Проверки в среде подготовки

Выполнен статический обзор и проверка локальных импортов. Node.js, PostgreSQL и браузер здесь недоступны: npm install, TypeScript, Prisma, сборка и интеграционные тесты НЕ запускались. Обновление требуется сначала проверить на тестовой копии базы.
