# Версия 0.3: защищённый вход, привязка устройств, закрытые QR-коды, сканер и PWA

## Что нового

### 1. Вход только с доверенных устройств
- После ввода верного пароля новый браузер/телефон получает статус «ждёт подтверждения» и показывает код вида `PLMZ-UB55`.
- Администратор открывает **Устройства**, вводит код, который ему назвал пользователь, и нажимает «Подтвердить». Вход на устройстве завершится автоматически (страница опрашивает сервер раз в 4 секунды, заявка живёт 30 минут).
- Сессия привязана к cookie устройства: украденная cookie сессии без cookie устройства не работает. При блокировке устройства его сессии завершаются сразу.
- Каждый пользователь подтверждает каждое своё устройство отдельно. Администратор видит IP, браузер и последнюю активность и может заблокировать или удалить устройство.
- Нельзя заблокировать последнее доверенное устройство администратора, чтобы не потерять доступ.

**Первый вход администратора** (доверенных устройств ещё нет) подтверждается из консоли сервера:

```sh
# Dokploy: Docker → контейнер app → Terminal
npm run device -- list
npm run device -- approve PLMZ-UB55
# Обычный Docker Compose
docker compose exec app npm run device -- approve PLMZ-UB55
```

Код также печатается в логи приложения (`[device] Новое устройство ждёт подтверждения…`).

> iPhone: установленное PWA хранит cookies отдельно от Safari. Устанавливайте приложение на экран «Домой» **до** входа и подтверждайте устройство уже из установленного приложения.

### 2. Двухфакторная аутентификация (TOTP)
- **Безопасность → Включить 2FA**: QR для Яндекс Ключа, Google Authenticator, Aegis, 2FAS. После этого при входе требуется 6-значный код. Повторное использование кода блокируется.
- Администратор может сбросить 2FA пользователю, потерявшему телефон (Пользователи → «Сбросить 2FA»).
- Секреты 2FA шифруются ключом `APP_SECRET`. **Не меняйте APP_SECRET после включения 2FA**, иначе коды перестанут приниматься (поможет только сброс 2FA).

### 3. Ограничение подбора пароля
- Не более 10 попыток на email за 15 минут (в БД) и 30 попыток с одного IP (в памяти процесса). IP берётся из `X-Real-IP` (его выставляют Traefik в Dokploy и Caddy).
- Время ответа для несуществующего email выровнено, чтобы нельзя было перебирать адреса.

### 4. Закрытые QR-коды
- На этикетке теперь не ссылка, а служебный текст `SINV1:<случайный токен>`. Обычная камера покажет только этот текст, а не адрес сайта.
- Код понимает только встроенный сканер и только у вошедшего пользователя с доверенного устройства и с правами на направление объекта.
- Токен случайный, не содержит ID и инвентарный номер. Его можно **перевыпустить** в карточке объекта: старая наклейка сразу перестанет работать.
- Старые этикетки со ссылками `?asset=` сканер пока понимает для плавного перехода. Перепечатайте их, чтобы на наклейках не оставался адрес сайта.

### 5. Встроенный сканер
- Кнопка **«Сканировать QR»** в шапке (на телефоне — плавающая кнопка внизу справа).
- Chrome/Android использует системный `BarcodeDetector`, iPhone и Firefox — библиотеку jsQR. Есть сканирование с фото и ручной ввод кода.
- После сканирования открывается карточка. Если идёт инвентаризация, в карточке есть кнопки «На месте» и «В другом помещении…», а также «Сканировать следующий». Так можно провести инвентаризацию, просто обходя кабинеты с телефоном.
- Камера работает только по **HTTPS**.

### 6. PWA
- Манифест, иконки, установка на экран «Домой» (Android: кнопка «Установить приложение», iPhone: «Поделиться» → «На экран „Домой“»). Ярлык «Сканировать QR» в долгом нажатии на иконку (Android).
- Service worker кэширует только статические файлы сборки и иконки. Данные об имуществе, API, этикетки и вложения **не сохраняются на устройстве**. Без сети показывается страница «Нет соединения».

## Обновление существующей установки

1. Резервная копия БД и volume `files` (см. README).
2. Добавьте в `.env` / Dokploy Environment: `APP_SECRET=$(openssl rand -hex 32)`, проверьте `APP_ORIGIN=https://ваш-домен` без завершающего `/`.
3. Пересоберите приложение и примените SQL один раз:

```sh
docker compose stop app
docker compose build app
docker compose run --rm app npx prisma db execute --file prisma/upgrades/0.3.sql --schema prisma/schema.prisma
docker compose up -d --force-recreate app
```

4. Все старые сессии станут недействительными. Войдите как администратор и подтвердите своё устройство командой `npm run device -- approve <код>`. Затем подтверждайте устройства остальных в разделе «Устройства».
5. Включите 2FA для администратора. Перепечатайте QR-этикетки.

Новая установка: вместо SQL выполните `npx prisma db push` и `npm run seed`, как в README.

## Деплой в Dokploy

Образ собирает GitHub Actions, подробности в **DEPLOY-GITHUB.md**. Кратко:

1. Create Project → Create Service → **Compose**, источник — приватный Git-репозиторий. Compose Path: `./compose.dokploy.yaml`. Autodeploy в Dokploy выключите.
2. Environment:
   ```dotenv
   DB_PASSWORD=<32 случайных латинских букв/цифр>
   APP_ORIGIN=https://inventory.ваш-домен.ru
   APP_SECRET=<openssl rand -hex 32>
   ADMIN_EMAIL=admin@school.local
   ADMIN_PASSWORD=<уникальный, от 14 символов>
   SCHOOL_NAME=Моя школа
   IMAGE=ghcr.io/<логин>/<репозиторий>:latest
   ```
3. Domains → Add Domain: Service `app`, Port `3000`, HTTPS on, Certificate Let's Encrypt. A-запись домена заранее направьте на IP сервера.
4. Deploy. Затем Docker → контейнер `app` → Terminal:
   ```sh
   npx prisma db push      # только первая установка
   npm run seed            # только первая установка
   ```
5. Откройте сайт, войдите, подтвердите устройство: `npm run device -- approve <код>`.
6. Backups: в Dokploy можно настроить расписание для volume и S3-хранилище. Отдельно делайте `pg_dump` (см. README).

Порты PostgreSQL наружу не публикуются. Откройте в firewall только 22, 80, 443 (и 3000 для панели Dokploy, лучше по IP или через SSH-туннель).
